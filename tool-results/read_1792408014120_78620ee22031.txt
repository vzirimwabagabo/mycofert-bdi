    75→   104→   104→
    76→   105→   105→| User Data Field | Bound to Typography Role | Notes |
    77→   106→   106→|-------------|-------------|------|
    78→   107→   107→| **Company/entity name** (e.g. "GREENTECH") | **Hero Title** (45-65pt Heavy) | Company name is the **absolute visual center**, largest font, heaviest weight |
    79→   108→   108→| **Report type/subtitle** (e.g. "2025 Annual Report Summary") | **Kicker** (16pt, letter-spacing 3pt, opacity 60%) | Report name is decorative supplementary text, placed in small text position at top-left/above title |

    85→   114→   114→1. If user provides only one name → treat as company/entity name, bind to Hero Title
    86→   115→   115→2. If user provides two names → shorter/more brand-like → Hero Title; longer/descriptive → Kicker or Summary
    87→   116→   116→3. If user explicitly labels "title" and "subtitle" → title → Hero Title, subtitle → Kicker
    88→   117→   117→4. **Never use report type names (e.g. "Annual Report", "White Paper") as Hero Title's largest text** - report type is always Kicker-level decorative text
    89→   118→   118→
    90→   119→   119→### The Summary Block Rule (Anti-Void Iron Rule) 
    91→   120→   120→
    92→   121→   121→> Every cover MUST include a Summary/Description text block. If the user provides no summary, the system MUST auto-generate one.
    93→   122→   122→
    94→   123→   123→**Why:** A cover with only a title and date looks barren. The Summary block physically fills 2-4 lines of space, preventing the "empty field" aesthetic.
    95→   124→   124→
    96→   125→   125→**Auto-generation rule:** When no summary/description is provided:
    97→   126→   126→```python
    98→   127→   127→# Generate a default summary
    99→   128→   128→if not summary_text:
   100→   129→   129→    summary_text = f"This report was generated by {org_name or 'the system'}, containing comprehensive data analysis and insights."
   101→   130→   130→    # Or in English:
   102→   131→   131→    # summary_text = f"This report presents comprehensive analysis and key insights prepared by {org_name or 'the organization'}."
   103→   132→   132→```
   104→   133→   133→
   105→   134→   134→**Constraints:**
   106→   135→   135→- Width: template-specific (typically `W * 0.5` to `W * 0.6`)
   107→   136→   136→- Lines: 2-4 lines (auto-wrap at width boundary)
   108→   137→   137→- Never truncate summary - if too long, reduce to 4 lines max with `...`
   109→   138→   138→
   110→   139→   139→### Font Weight Fallback
   111→   140→   140→
   112→   141→   141→- If font family lacks Black/Heavy weight → use Bold + slightly larger size (+4pt)
   113→   142→   142→- If font family lacks Light weight → use Regular + increased letter-spacing (+1pt)
   114→   143→   143→- CJK fonts: Noto Serif SC for Regular/Light roles; for Heavy/Black → increase size by 15% to compensate for single-weight CJK fonts
   115→   144→   144→- English kickers/footers: **FORCE UPPERCASE** via code (`text.upper()` / `toUpperCase()`)

   119→   148→   148→## A0.3 - Z-Index Layer Management
   120→   149→   149→
   121→   150→   150→All cover elements must be rendered in strict layer order. No exceptions.
   122→   151→   151→
   123→   152→   152→| Layer | Z-Index | Contents | Rules |
   124→   153→   153→|-------|---------|----------|-------|
   125→   154→   154→| **Layer 0** (base) | 0 | Background fill (white / light gray) | Always rendered first; full page |
   126→   155→   155→| **Layer 1** (background) | 1 | Grids, watermark letters, decorative blocks, large clipped graphics | **MUST enable clip-path** - background elements may extend beyond logical bounds but must be clipped to page physical bounds. Never let background elements inflate PDF page size. |
   127→   156→   156→| **Layer 2** (structure) | 2 | Ultra-thin divider lines, sidebars, corner crop marks | Structural guides that define spatial zones |
   128→   157→   157→| **Layer 3** (content) | 3 | All readable text content | Rendered last, always on top |
   129→   158→   158→
   130→   159→   159→### Clip-Path Enforcement
   131→   160→   160→
   132→   161→   161→```css
   133→   162→   162→/* clip background overflow — ONLY on Layer 1 */
   134→   163→   163→.cover-bg-layer {
   135→   164→   164→  position: absolute;
   136→   165→   165→  inset: 0;
   137→   166→   166→  overflow: hidden;  /* MANDATORY */
   138→   167→   167→  z-index: 1;
   139→   168→   168→}
   140→   169→   169→```
   141→   170→   170→
   142→   171→   171→> ⚠️ **Clip scope = Layer 1 ONLY.** `overflow: hidden` must ONLY be on the Layer 1 background container. Layer 2 (lines) and Layer 3 (text) containers must NOT have `overflow: hidden`.
   143→   172→   172→
   144→   173→   173→###  Anti-Clip Bug (Layer 3 Text Truncation Fix)
   145→   174→   174→
   146→   175→   175→**Symptom:** Cover text is visible but truncated by an invisible boundary.
   147→   176→   176→
   148→   177→   177→**Root cause:** `overflow: hidden` scope too broad, clipping text in Layer 3.
   149→   178→   178→
   150→   179→   179→**Iron rule:**
   151→   180→   180→```html
   152→   181→   181→<!-- ✅ CORRECT - overflow:hidden only on Layer 1 -->
   153→   182→   182→<div class="cover-layer-1" style="position:absolute; inset:0; overflow:hidden; z-index:1;">
   154→   183→   183→  <!-- Background decorative elements -->
   155→   184→   184→</div>
   156→   185→   185→<div class="cover-layer-2" style="position:absolute; inset:0; z-index:2;">
   157→   186→   186→  <!-- Structure lines, no overflow:hidden -->
   158→   187→   187→</div>
   159→   188→   188→<div class="cover-layer-3" style="position:absolute; inset:0; z-index:3;">
   160→   189→   189→  <!-- Text content, no overflow:hidden -->
   161→   190→   190→</div>
   162→   191→   191→
   163→   192→   192→<!-- ❌ WRONG - global overflow:hidden clips text -->
   164→   193→   193→<div class="cover-container" style="overflow:hidden;">
   165→   194→   194→  <div class="layer-1">...</div>
   166→   195→   195→  <div class="layer-2">...</div>
   167→   196→   196→  <div class="layer-3">...</div>  <!-- Text gets clipped! -->
   168→   197→   197→</div>
   169→   198→   198→```
   170→   199→   199→
   171→   200→   200→###  No Page Border/Frame
   172→   201→   201→
   173→   202→   202→**Symptom:** A rectangular border appears around the entire cover page.
   174→   203→   203→
   175→   204→   204→**Iron rule:**
   176→   205→   205→```css
   177→   206→   206→.cover-page {
   178→   207→   207→  border: none !important;
   179→   208→   208→  outline: none !important;
   180→   209→   209→  box-shadow: none !important;
   181→   210→   210→}
   182→   211→   211→```
   183→   212→   212→
   184→   213→   213→###  Minimum Spacing Between Decorative Lines and Text (Line-to-Text Spacing)
   185→   214→   214→
   186→   215→   215→**Symptom:** Decorative lines on the cover (Layer 2 dividers, corner marks, sidebar edges) are flush against or overlapping with text.
   187→   216→   216→
   188→   217→   217→**Iron rule:**
   189→   218→   218→```
   190→   219→   219→Minimum spacing between decorative lines and any text content = U (= W * 0.05)
   191→   220→   220→i.e., at least 1 U of whitespace between line edges and text edges
   192→   221→   221→```
   193→   222→   222→
   194→   223→   223→| Line Type | Minimum Spacing | Notes |
   195→   224→   224→|---------|---------|------|
   196→   225→   225→| Horizontal divider | `U` above and below the line | Line must not be flush against title or body text |
   197→   226→   226→| Vertical sidebar edge | `U` to the right of the line | Text inside sidebar must maintain spacing from the edge |
   198→   227→   227→| Ultra-thick anchor line (Template 01) | `2 * U` to the right of the line | Thick line and title need ample breathing room |

   272→   301→   301→## S3.0 - Cover Overlap Validation (MANDATORY)
   273→   302→   302→
   274→   303→   303→**After generating the cover HTML and before rendering to PDF, run:**
   275→   304→   304→
   276→   305→   305→```bash
   277→   306→   306→node "$PDF_SKILL_DIR/scripts/cover_validate.js" cover.html
   278→   307→   307→```
   279→   308→   308→
   280→   309→   309→This detects text-vs-decorative-line overlaps by rendering the HTML and measuring actual bounding boxes. Exit code 1 = overlap found, must fix before generating the PDF.
   281→   310→   310→
   282→   311→   311→The minimum gap between any text element and any decorative line is **1U (= 5% of page width ≈ 40px on A4)**. This catches the exact bug shown in the "text overlapping decorative lines" screenshots.
   283→   312→   312→
   284→   313→   313→**If the check fails:**
   285→   314→   314→1. Adjust the decorative line's Y position to maintain ≥ 1U gap from the nearest text
   286→   315→   315→2. Or adjust the text block's position/size to avoid the overlap
   287→   316→   316→3. Re-run `cover_validate.js` until it passes (exit code 0)

   291→   320→   320→## S3.1 - Hero Title Overflow Protection (Title Line-Wrapping)
   292→   321→   321→
   293→   322→   322→**Rule:** Hero title must NEVER exceed its template's width boundary.
   294→   323→   323→
   295→   324→   324→1. If rendered width > max_width → word-wrap (CJK: any character; Latin: space/hyphen)
   296→   325→   325→2. Multi-line hero titles: **lock line-height to 1.15**
   297→   326→   326→3. Maximum lines: **3** — if 4+ lines needed, reduce font size by 4pt increments
   298→   327→   327→4. Minimum font size floor: **32pt** (below this, truncate with `...`)
   299→   328→   328→
   300→   329→   329→### Title Size vs Lines Quick-Reference (Template 01, zone B→C ≈ 225px)
   301→   330→   330→
   302→   331→   331→| Lines | With subtitle | Without subtitle |
   303→   332→   332→|-------|--------------|------------------|
   304→   333→   333→| 1 | ≤ 80pt | ≤ 80pt |
   305→   334→   334→| 2 | ≤ 55pt | ≤ 70pt |
   306→   335→   335→| 3 | ≤ 42pt | ≤ 48pt |
   307→   336→   336→
   308→   337→   337→**⚠️ CJK 3-line titles must reduce to ~42pt.** Do NOT use 50-80pt for 3-line CJK titles — it WILL overlap the Summary zone.

   312→   341→   341→## S3.2 - Zone Collision Detection
   313→   342→   342→
   314→   343→   343→After placing each text block, check if its bottom edge penetrates the next zone's top:
   315→   344→   344→
   316→   345→   345→1. **Reposition first:** Push the collided zone down by `overlap + 20px` gap. All downstream zones shift together.
   317→   346→   346→2. **Font reduction (if reposition insufficient):** Decrease title by 2pt increments. Floor: **32pt** for titles, 14pt for meta/summary.
   318→   347→   347→3. **Truncation (last resort):** If font reduction hits floor and still collides, truncate with `...`

   391→   420→   420→
   392→   421→   421→**Problem:** Content clusters at top of page, bottom 40%+ is dead whitespace.

   399→   428→   428→| **Normal** (fill 50-80%) | `H * 0.30` | `H * 0.48` | `H * 0.70` |
   400→   429→   429→| **Dense** (fill > 80%) | `H * 0.20` | `H * 0.40` | `H * 0.65` |
   401→   430→   430→
   402→   431→   431→**CJK Title Size Compensation:** CJK characters appear smaller at same pt size. Increase by 15-20%:
   403→   432→   432→- CJK Hero Title: 50-80pt (Latin: 45-65pt)
   404→   433→   433→- CJK Kicker: 11-12pt (Latin: 9pt)
   405→   434→   434→- CJK Summary: 17-20pt (Latin: 16-18pt)

   408→   437→   437→- [ ] No cover has >40% dead whitespace at the bottom

   414→   443→   443→## S3.9 - Percentage Positioning Requires Known-Size Container
   415→   444→   444→
   416→   445→   445→**Problem:** `top: XX%` resolves against containing block’s height. If height is undefined (all children absolutely positioned), percentages collapse and elements stack.
   417→   446→   446→
   418→   447→   447→**Iron rule:** Container with `top: XX%` children MUST have deterministic height (`height: 100%`, `inset: 0`, or `top` + `bottom` pair).
   419→   448→   448→
   420→   449→   449→```css
   421→   450→   450→/* ✅ Safest: flat structure with px values */
   422→   451→   451→.cover { position: relative; width: 794px; height: 1123px; }
   423→   452→   452→.kicker { position: absolute; top: 225px; left: 95px; }
   424→   453→   453→.title  { position: absolute; top: 292px; left: 95px; }
   425→   454→   454→
   426→   455→   455→/* ✅ OK: wrapper with inset:0 gives it known height */
   427→   456→   456→.content-left { position: absolute; inset: 0; width: 55%; }
   428→   457→   457→.title { position: absolute; top: 26%; }  /* 26% of 1123px ✓ */
   429→   458→   458→
   430→   459→   459→/* ❌ BANNED: wrapper without height, percentage is undefined */
   431→   460→   460→.content-left { position: absolute; left: 12%; top: 0; width: 55%; }

   437→   466→   466→# PART 4: COVER COLOR RULES
   438→   467→   467→
   439→   468→   468→> Cover colors must be consistent with the body color system - they cannot exist independently.
   440→   469→   469→> **The cascade palette CSS output includes `--c-*` aliases** that map directly to cover template variables. Paste the CSS output into cover HTML's `:root` block — template 01 works without any manual color translation.
   441→   470→   470→
   442→   471→   471→```
   443→   472→   472→Cover primary    = Body theme color
   444→   473→   473→Cover secondary  = Primary lightness variant (±20% lightness)
   445→   474→   474→Cover background = Pure white / very light gray / primary at 5-8% opacity
   446→   475→   475→```
   447→   476→   476→
   448→   477→   477→### Absolutely Forbidden
   449→   478→   478→
   450→   479→   479→- ❌ Dark large-area solid backgrounds (dark blue, dark green, black filling the page)
   451→   480→   480→- ❌ Gradient backgrounds (any `linear-gradient` / `radial-gradient` as large-area fill)
   452→   481→   481→- ❌ High-saturation color schemes
   453→   482→   482→- ❌ Rainbow / multi-color gradients
   454→   483→   483→- ❌ Dense textures or patterns
   455→   484→   484→- ❌ Piling on decorative elements - restraint > clutter
   456→   485→   485→- ❌ More than 2 typefaces on a cover
   457→   486→   486→- ❌ Centered text + gradient/solid background (PowerPoint aesthetic)
